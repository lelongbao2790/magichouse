## Active NFR Requirements

### NFR-01 — Property-Based Testing (PBT Extension, Full Enforcement)

**Status**: Active — all 10 PBT rules enforced as blocking constraints.

**Framework**: `fast-check` v3.x (TypeScript-native PBT library)
**Test Runner**: Vitest (selected — Q1 answer A)

**Scope**: All five pure generator functions in `learning-zone.tsx`:
- `generateAdditionQuestion()`
- `generateSubtractionQuestion()`
- `generateTimesTableQuestion(language)`
- `generateDistractors(correct, strategy, context, ...)`
- `insertAtRandom(correct, distractors)`

**PBT Requirements per function** (to be enforced at Code Generation):
- Custom domain-scoped generators (PBT-07): number ranges must be constrained to business rules (e.g., operands [1,100], multiplier [2,9])
- Shrinking enabled (PBT-08): must not be disabled; failing seeds must be logged
- CI seed logging (PBT-08): Vitest config must log or fix the fast-check seed on every run
- Complementary example-based tests required alongside PBT (PBT-10)

### NFR-02 — Code Consistency
All new code in `learning-zone.tsx` must follow the existing file's conventions:
- Same import ordering pattern
- Same `useMemo` pattern for question generation
- Same category card array structure
- TypeScript strict mode compatible

### NFR-03 — Synchronous Generation
All generator functions must be synchronous. No `async/await`, no Promises, no lazy imports. Questions must be ready before the component renders the category grid.

### NFR-04 — Test Infrastructure Readiness
All new interactive elements must include `data-testid` attributes per the map defined in `frontend-components.md`:
- `tab-grade2`, `quiz-addition`, `quiz-subtraction`, `quiz-timesTable`

### NFR-05 — Translation Key Consistency
New translation keys must follow the `translations[section][key][language]` structure. New sections: `grade2`, `quizAddition`, `quizSubtraction`, `quizTimesTable`. Keys must be added to `data/translations.ts` as a `const` object with `vi` and `en` string values.
